# CEAC OS — Visual Fidelity Contract

Status: BINDING
Date: 1 October 2026
Programme: Visual Fidelity & Interaction Closure

## 1. Product ambition

CEAC OS must feel like a premium organisational operating system, not an HR database with modules attached and not a generic administration template.

Product promise:

**People. Work. Ministry. Impact.**

The visible experience must feel:
- composed rather than assembled;
- premium rather than decorative;
- calm but information-rich;
- visually intelligent;
- role-specific;
- context-aware;
- purposeful;
- modern;
- highly legible;
- responsive by design.

The target is not merely “clean enterprise software.”

## 2. Protected V2 foundation

Preserve:
- Instrument Sans;
- Lucide-backed CEAC semantic icon system;
- existing semantic tokens unless deliberately evolved through this contract;
- dark CEAC navigation identity;
- blue workspace action language;
- current role routing;
- responsive/accessibility foundation;
- reduced-motion support;
- truthful data and empty states;
- all domain/security contracts.

Do not create a third competing design system.

## 3. Visual failure patterns to remove

The following are material drift:
- white-card-everywhere composition;
- every section being the same rounded rectangle;
- nested cards without a real information-grouping reason;
- giant unused pale canvases;
- equal visual weighting of primary and secondary information;
- generic admin-template page composition;
- excessive explanatory prose;
- decorative charts;
- fake KPIs or unsupported trends;
- desktop layouts merely compressed onto mobile;
- weak or inconsistent icon optical weight;
- oversized headings on operational pages;
- low-density pages that force unnecessary scrolling;
- dense pages without a clear action hierarchy.

## 4. Global visual parameters

These are defaults, not excuses to ignore route context.

Typography:
- Instrument Sans remains the UI family.
- Operational text floor: 12px.
- Typical metadata: 12–13px.
- Typical body/row text: 13–15px.
- Section headings: generally 15–18px.
- Page titles: generally 24–32px depending on role/context.
- Large display type is reserved for true hierarchy moments, not every screen.

Icons:
- one semantic Lucide language;
- navigation typically 18–20px;
- row/action icons typically 16–18px;
- consistent stroke weight around the accepted V2 optical standard;
- no emoji as navigation/product controls.

Spacing/composition:
- desktop/laptop primary gutters generally 20–28px;
- operational internal gaps generally 8/12/16/20/24 rhythm;
- dashboard columns should use the available width intentionally;
- avoid full-width blank expanses when useful operational context exists;
- preserve visual breathing room without reducing information utility.

Surfaces:
- cards are one tool, not the universal container;
- use flat queues, tables, timelines, split panes, drawers, calendars, profile layouts, activity feeds, charts and progress tracks where they communicate better;
- bounded cards should correspond to a real object or meaningful group.

Colour:
- CEAC identity/navigation remains dark navy/teal family;
- workspace primary action remains blue;
- semantic state colour is restrained and meaning-led;
- do not make the product colourful merely to look premium.

Motion:
- purposeful, restrained, normally about 150–220ms;
- use for opening, focus, movement, status change and success confirmation;
- reduced-motion preference must remain respected;
- motion never carries the only indication of state.

## 5. Role character

### Staff — calm, personal, focused

Primary question: “What matters now?”

Staff must have the least administrative complexity and least analytics.

Priority:
1. primary next action;
2. Needs you;
3. Waiting / updates;
4. Coming up;
5. subtle personal/weekly context.

Mobile is first-class. Staff must not become an analytics dashboard.

### Manager — team command centre

Primary character: operational, coordinated, decision-led.

Primary hierarchy:
1. Needs your decision
2. Work you gave out
3. Team workload
4. Projects needing attention
5. Money context
6. Upcoming commitments

Manager must not feel like Staff with extra menu items.

Use the desktop/laptop canvas to create a command-centre composition, including schedule/calendar context where it materially helps.

### Administration / HR — organisation operations console

Primary character: structured, efficient, record-oriented.

Higher density is permitted, but not architectural clutter.

Prefer:
- operational queues;
- direct resolution;
- strong people/employee workspaces;
- useful tables;
- split views;
- intelligent setup/unconfigured states.

Do not turn every record into a card.

### Executive / Group Pastor — executive briefing

Primary character: highly summarised, visual where justified, exception-led, decisive.

Priority:
- Needs your attention;
- ministry movement;
- departments;
- major projects;
- goals;
- financial context;
- reporting;
- commitments.

Summarise first; drill down second.
Executive must not look like reduced Admin.

## 6. CEAC premium composition DNA

The original CEAC premium mockup establishes these owned composition principles:
- persistent dark navigation rail with strong active-state recognition;
- top command/search/action layer;
- compact greeting/context band rather than a blank title-only page;
- one clearly dominant “next/decision” area;
- schedule/calendar context used as an operational side rail on larger screens where useful;
- distinct attention, waiting and coming-up zones;
- compact destination/discovery layer rather than menu sprawl;
- varied information surfaces, not repeated identical cards;
- dense-but-readable lower work/team/project/money surfaces;
- responsive mobile experience with prioritised bottom navigation and a single dominant task/action.

Do not copy mockup sample data literally. Preserve the composition logic with authoritative CEAC data.

## 7. Data visualisation rule

Charts are allowed only when comparison is faster than reading records.

Good uses:
- movement over time;
- budget vs actual within one currency;
- work-status distribution;
- workload distribution;
- reporting completion;
- project timeline;
- attendance calendar;
- ministry-goal movement.

No chart may invent data, imply a score, or hide missing/unconfigured source information.

## 8. Interaction rules

- preserve context on drill-down;
- avoid repeated searches for the same person/project;
- put the primary action at the decision point;
- progressive disclosure for advanced controls;
- direct manipulation over technical forms where safe;
- show consequence before irreversible actions;
- keep history attributable;
- make role boundaries visible through available actions;
- do not duplicate data-entry paths;
- make empty/setup states actionable;
- use CEAC language, not backend terminology.

## 9. Hard visual acceptance statement

“Technically correct but visually generic” = FAIL.

“No major visual defect” = insufficient for acceptance.

The product must demonstrate the intended CEAC role character and composition at the evidence viewports before a VF substage can be accepted.
