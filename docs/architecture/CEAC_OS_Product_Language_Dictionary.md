# CEAC OS — Product Language Dictionary

**Purpose:** shared Staff/Manager terminology. Product screens should use these terms consistently unless a role genuinely needs a different phrase.

| Concept | Preferred product language | Avoid |
| --- | --- | --- |
| manager-created work | Assigned | task from manager, manager task |
| staff-created operational work | Agreed | self-created, personal task |
| staff-only work | Private | hidden task |
| work awaiting another person/unit | Waiting on | blocked person, stalled employee |
| submitted work | In review | pending approval where no approval is guaranteed |
| returned work | Sent back / Returned for correction | failed |
| finished accepted work | Completed | passed |
| unit/project conversation | Room | chat, channel when Room is meant |
| meeting attendee relationship | Participant / Invited | visible user |
| manager decision on submission | Review | moderation |
| work sent back | Return for correction | reject |
| authoritative supporting material | Evidence | proof where legal/probative meaning is not intended |
| work session | Work session | attendance timer, productivity timer |
| manager attention | Needs you | alerts everywhere |
| delivery concern | Delivery risk / Needs attention | poor performance |
| ordinary factual staff history | Record | scorecard |

## Writing rules

- Say what happened and what the person can do next.
- Do not expose database, RPC, RLS or PostgREST terminology.
- Do not imply productivity from attendance or work-session state.
- Do not label returned work as failure.
- Do not use performance-score language.
- Prefer concise action labels: Review, Return for correction, Approve, Open work, Follow up.
- Where privacy matters, state who can see the information.
