# FPG Acceptance Protocol

## Development commits
Run production build, affected tests, affected browser checks and reference screenshots.

## Meaningful FPG boundaries
Require CI, Migration Replay, Account Security, applicable browser/role tests, and direct reference-parity evidence.

## Gold-standard record
Every visual acceptance record must state:
- FUNCTIONAL CONTRACT PRESERVED: YES/NO
- SECURITY/AUTHORITY PRESERVED: YES/NO
- REFERENCE COMPONENT PARITY: YES/NO
- RESPONSIVE ACCEPTANCE: YES/NO

“Looks good”, “premium”, “clean”, “same principles” and “no major defect” are not substitutes for literal component parity.

## Final closure
Complete cumulative Quality Gate, production deployment, authenticated Staff/Manager/Administration/Executive smoke, desktop/mobile inspection, and security/database verification. Do not weaken final acceptance.
